## 研究问题与使用边界

业务方向是研究中文投资社区中散户表达所携带的信息，检验其是否能改善机会选择。当前具体实验是：在同样的标题输入上，对照 K3 词表与 27B 语义识别，观察模型能否补充遗漏、减少误伤，以及这些变化对日级观测有什么影响。

情绪、看法、交易动作、表达方式和讨论对象需要分别保留。辱骂不自动等于恐惧，看跌不自动等于卖出，买入不自动等于兴奋。规则未命中、模型未表达、模型无法判断，也都不能命名为“情绪平静”。

标签服务于标注与对账，原始分数和语境应保留下来，供以后检验不同组合方式。当前没有经过验证的单一“情绪真值”、盈利权重或分数校准方案。不同标签不能直接用固定权重合成收益结论。

本轮已经看到模型在抽样审计中的用途：让词表的遗漏与误伤更容易暴露。但“能发现盲点”不等于“已产出有效的新规则”。没有实施并验证新的词表或模式，也没有发现新的交易规律；不要把“规则发现”写成已验证能力。

## 数据如何进入模型

每个请求只包含下面五个字段：

```json
{
  "id": "N0003",
  "published_at": "2025-08-14T09:58:20+08:00",
  "stock_code": "300054",
  "stock_name": "鼎龙股份",
  "text": "今天红盘问题不大"
}
```

输入为原始标题，没有正文、当日其他帖子、行情、词表命中、当日密度、z 值或未来收益。股票名称只提供指代线索。规则和日期统计等信息放在本地 sidecar 中，不能混入模型输入，以免对照被规则答案或选择条件污染。

## 提示词与输出到底是什么

三个 K3 批次的提示词模板、含义定义和实际展开提示词均一致。本次复核指出的错误没有写回提示词，也没有反馈给原来的模型调用。

实际提示词约 2,276 个字符。模型先输出自由观察 `observations`，再回答固定四项 `checks`：

| 字段 | 当前定义 |
| --- | --- |
| `bearish_expression` | 作者认可的负向价格／前景判断，或对下跌、弱势的负面评价；不只包含预测未来下跌 |
| `sell_declaration` | 作者自己的卖出、减仓、清仓、退出陈述或明确意向 |
| `high_arousal_expression` | 明显强烈的情绪或表达，可为正面或负面 |
| `buy_declaration` | 作者自己的买入、加仓、重仓参与陈述或明确意向 |

自由观察可以包含恐惧、失望、希望、讽刺等更多含义，并非仅允许四个标签。四项是当前对账用的命题，不是此前的七头训练模型。

每项观察或声明保留 `quote`、`reason`、`subject`、`target`、`time`、`time_text`、`state`、`intensity`、`support`。其中：

- `intensity` 是表达强度，不是正负方向、持仓比例、收益预测或正确率。
- `support` 是模型对文本证据支持度的自评，未经校准，0.9 不代表 90% 正确。
- 不适用或未知可以为 `null`／`unknown`；未知不能默认为 0 或平静。
- 肯定、明确否认、歧义分别保留。一个帖子可以同时包含多种情绪、多个对象和不同时间的动作。
- 没有用 0.9 阈值删除标签或观察，也没有将支持度与强度相乘后定义为最终情绪值。

当前运行是每帖一次请求，关闭 thinking，输出短理由；没有在线多 agent 复核。后续 80 条阅读检查是本会话的离线分析，不是模型本身的第二轮推理。

## 新实例的启动与续跑顺序

当前批次已完成，以下是以后确有新批次或缺项时的操作顺序，不是立即重跑指令。

1. **先在本地准备好。** 明确股票、日期、输入数、需要对照的变量、输出目录、复用关系和预计费用。校验输入唯一编号、冻结提示词与运行包，在本地跑已有模拟检查。不要等 GPU 开机后才选样本、写导出器或修网页。
2. **连接后先查现状。** 核对本次租赁期限、实际 GPU、权重分片及已有验证记录、磁盘余量、8000 端口服务、runner 锁和进程。已经健康运行的模型直接复用，不重复加载或下载。
3. **建立本轮时间边界。** 停止派发新请求、允许在途请求收尾、最终备份分别留时间。本轮使用过 240 秒收尾和约 10 分钟备份余量；新实例重新计算，不能复制 10 月 13 日的 epoch。
4. **启动批次前先保证结果可取回。** 配置独立备份与新鲜度检查，验证一次远端到本地的下载。密码只留进程内存，不写进文件、命令参数、提示词或日志。
5. **核对服务健康后运行。** 使用同一模型服务派发请求。格式问题记录原文后继续，不让逐条修格式阻塞 GPU；连续服务失败则诊断，而不是持续烧钱发送失败请求。
6. **按缺项续跑。** 同批续跑必须通过原输入、提示词、模型配置、校验器与 runner 哈希核对。改动语义或脚本应开新实验目录，不能伪装为原批次断点。
7. **完成后核对并收尾。** 按输入集合核实唯一 ID、缺项、复用出处、完整原始回执及本地快照哈希。已有授权的下一批才能接续；否则完成收尾。停止程序不等于平台停止租赁计费。
