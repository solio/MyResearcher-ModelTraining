# CPU 并行整理说明

本工作只读取本批原始请求与回答，不发起推理，不改提示词、标签、分数或原始校验状态。

- 远端每 30 秒读取新增完整回答，核对请求与冻结输入是否一致、返回编号、结束原因、每项引用与时间词的原文位置。
- 包含格式被拒的回答：完整保存模型原话和 JSON，问题精确标到字段。不会把“原文匹配”当作“语义正确”。
- 压缩打包后校验哈希并同步回本地。本地才合并股票、上游日期、命中类型等原始字段，不把规则结果或日期统计上传给模型。
- GPU 仍用既有 8 并发运行。CPU 整理单进程、nice +15、空闲 IO 优先级、384 MiB 内存上限、120 秒累计 CPU 时间上限。每轮之间休眠 30 秒。
- 跟随本轮结束，最迟在 GPU 截止时间后 30 秒终止整理；不续费、不新增样本。

## 文件

- `k3-raw-return.jsonl`：本地原始字段 + 完整模型回答 + 逐项机械检查，可交给 K3。只含已经返回的帖子，持续增长。
- `model-answers.jsonl`：不含规则侧元数据的完整模型回答与机械检查。
- `output/mechanical-issues.jsonl`：引用、时间词、编号等问题列表。
- `output/summary.json`：整理进度；数量不是正确率。
- `delivery-manifest.json`：本地同步时间和结果哈希。
- `remote-launch.json` / `sync.pid`：远端 CPU 进程与本地同步进程记录。

如果 CPU 整理任务失败，GPU 队列与原有原始结果备份仍独立运行。保留原始回执后可重新生成这些衍生文件。
